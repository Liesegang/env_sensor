# Card v2 firmware

`card/hardware/v2/card_env_sensor_1.fsch` 用のnRF Connect SDK / Zephyrアプリ。
1秒ごとに実測値を取得し、1分ごとにBLEで毎秒の記録をスマートフォンへ同期する。
未受信分はSDと未書込RAMから、確認応答付きのページで再送する。
CO₂が1200 ppmを超えたときはブザーで短音を5回鳴らす。
毎秒の測定をRAMへため、10分ごとにSDへまとめて追記する。
電子ペーパーはグラフモードの起動時と10分ごとに直近24時間のグラフ・数値カードを更新する。
画像モードでは定期更新せず、画像の受信・スイッチによる切替などの操作時に描画する。
S1は50ms周期で確認する。PUSH短押しはグラフ／画像、3秒長押しは再登録用PIN、
上はSDの保存履歴、下は現在のグラフを選ぶ。長押し後はボタンを離してよい。
CPUはSystem ONで動作し、deep sleep／System OFFは使わない。

SW1はVOUT2から周辺回路への電源を切り替える。MCUのVDD、PMICのVDDIOと
SWDコネクターのVTrefはSW1の手前のVOUT2へ直結している。
USB／LiPoからPMICが動いていれば、SW1 OFFでもMCUは実行・書き込みできる。
センサー・SD・ブザーを動かすにはSW1 ONが必要。表示器は別のBUCK1電源を使う。

- IC5 P1.00 (`ENABLE`) は active-low。LowでFET3がオンになり、BUZZ1の電源`+V`が入る。
- IC5 P1.01 (`BUZZER`) はPWM20のchannel 0で駆動し、待機中はGPIO出力Lowに固定する。
- 起動時は電源をオフ、ブザー駆動端子をLowにしてから電源をオンにする。P1.00/P1.01を使うためLFXOは無効。
- I²CはTWIM30、SCL=P0.03、SDA=P0.04、100kHz。R12/R13の外付けプルアップは`+V`につながるため、電源投入後に通信する。

読み取り対象はOPT4001（照度）、BME690（温度・湿度・気圧・ガス抵抗）、
SGP41（VOC / NOx rawと指数）、STCC4（CO₂）とSTCC4経由のSHT45（温度・湿度）。
SFA40アルデヒドセンサーは未実装でもビルドに含め、未接続なら定期的に再検出する。
未接続・暖機中・無効値は欠測として扱い、接続後はHCHOもSD・BLE・画面に反映する。
各ドライバーは[共通ライブラリ](../../shared/firmware/driver/)を`outdoor`と共有する。

v2回路の`PARTS`属性はIC11=`BME690`、IC6=`SPG41`（SGP41の表記違い）、
IC7=`SHT4x-Axx`。シンボルのBME688・SGP40・SHT40-BD1B-R2ではなく、
実装指定と確認済みのSHT45に合わせた。
STCC4の起動時自己診断で補助I²CのSHT45接続を判定する。未接続なら
BME690の温湿度を表示とCO₂補償へ使う。
BME690も読めない周期は25°C・50%RHを使う。

## CO₂アラーム

有効なCO₂測定値が厳密に1200 ppmを超えたとき、100 msの短音を開始間隔1000 msで
5回鳴らす。1200 ppmちょうどでは鳴らさない。超過が続いても毎分は繰り返さず、
有効な値が1200 ppm以下へ戻ると次の超過に備える。未取得・測定エラー・負の値は
鳴動や再通知の解除に使わない。

v2のBUZZ1はUGCT7525。メーカー資料の共振周波数2700 Hz、50% dutyの矩形波に合わせ、
TR1をP1.01のhardware PWMで駆動する。delayable workの状態機械なので、
5回の鳴動待ちでセンサー測定・BLE・表示処理を止めない。
各短音の終了時にdutyを0にし、PWMをruntime suspendしてからP1.01を出力Lowに戻す。
ドライバーエラー時は残りの短音を取り消し、停止処理を実行する。
RTTの`CO2 ALERT: PWM start/stop`に回数と実際の起床時刻を記録する。

`CONFIG_CARD_ALARM_TEST_ON_BOOT=y`は書込検証用の一度だけの鳴動を追加する。
アラームへ1201 ppmを渡すだけで、実測値・SD・BLE・グラフのデータは変更しない。
通常設定は`n`。ホスト検証は`bash tests/run_co2_alarm_tests.sh`。

2026-10-11の実機テストでは、PWMの開始・停止を5回確認した。
開始間隔は1000/1000/1001/1000 ms、各短音は100 msで、最後にPWM停止・端子Lowへ戻った。

参照: [UNIVERSAL UGCT7525AN4メーカー資料](https://akizukidenshi.com/goodsaffix/UGCT7525AN4.pdf)

nRF Connect SDK v3.4.1を使う。接続したJ-Linkの番号は`nrfutil device list`で確認する。

```sh
cd card/firmware
./scripts/fw build
./scripts/fw flash 69730357
# nrfutilでDebugPortのエラーが出る場合は、インストール済みSEGGERツールを使う。
./scripts/fw flash-jlink 69730357
./scripts/fw rtt 69730357
```

`flash`はビルド後、既存のアプリ領域を`.local/before_flash_*.hex`に保存してから
書き込み・検証する。`recover`や全消去は行わない。
`flash-jlink`も書き込み前にアプリ領域全体を`.bin`へ保存し、サイズを確認する。
SEGGERの実行パスは`JLINK_COMMANDER`で指定できる。処理ログは`.local`に保存する。
`printk()`はSWDのSEGGER RTTへ出力する。
`rtt`は`.local/rtt.log`へログを書き、任意のキーかCtrl+Cで終了する。

実機ではOPT4001、BME690、SGP41、STCC4経由のSHT45から値を確認済み。
OPT4001は一時的に通信できなかったが、再確認時にID `0x0121`と照度の連続測定を確認した。
通信が切れたセンサーは、他の測定を止めずに初期化を再試行する。
v2の指定部品はOPT4001DTSRで、IC2のVDD/ADDRは`+V`、C36は0.1 µF、
R12/R13は各5.1 kΩ。実機の照度センサー横のコンデンサでは3.3 Vを確認済み。

## nPM1300の初期化・充電

`+V`投入後、センサー測定を始める前に`pmic_init()`を呼ぶ。
表示器電源のBUCK1を3.3 Vに設定して有効にし、PWRGOODと電圧設定を確認する。
v2はVSET1がGNDなので、BUCK1はソフトで起動する必要がある。
MCU用BUCK2の電圧設定は維持し、動作モードはAutoにする。

`pmic_charger_enable(4200, 32)`で1セルLiPo用の4.2 V・32 mA充電を有効にする。
接続バッテリーは400mAhの1セルLiPo。充電電流は32mAを維持する。
充電を一度停止し、電流・通常時／高温域の終止電圧を設定・照合してから有効にする。
v2のNTC端子はGND接続なので外部NTC監視を無効にし、内部温度保護と温度自動測定は有効にする。
USB入力電流制限と放電電流制限は既存設定を使う。

基板LED1はVSYSからnPM1300のLED1端子に接続されている。
`LEDDRV1MODE`を`CHARGING`に設定し、充電中はPMIC自身が点灯、終了すると消灯する。
USB・VBAT・充電enable・状態・エラー・電流・終止電圧を起動時にRTTへ出す。
VSYSとVBUSも内蔵ADCで測定し、2秒後に充電状態を再確認する。
1セルLiPoとUSB-Cの接続後、約3.69 VのVBAT、約5.15 VのVBUS、
定電流充電、充電エラーなし、LED点灯を確認済み。BUCK1のPWRGOODも確認済み。

## 電子ペーパーの表示

Waveshare 3.6inch e-Paper (E)、Spectra 6、ネイティブ400×600ピクセルを使う。
SPI20はSDと共用し、表示器はCS=P1.03、DC=P1.05、RESET_N=P1.07、
BUSY_N=P1.08。SCK=P1.04、MOSI=P1.06、mode 0・最大4 MHz。
BUCK1投入前にCSをHigh、RESETをLowへ固定する。

通信・初期化・画面更新・sleepは`shared/firmware/driver/epd3in6e`、
画面の描画は`shared/firmware/driver/epd_dashboard`が担当する。
`card/epaper_sample`から移植し、Arduinoと同ディレクトリへのビルド依存はない。
サンプルを削除しても表示コードはビルドできる。

横向き600×400の画面に8種類の数値カードと、10分slot×144点の24時間グラフを描く。
各slotは最後の実測値を保持する。TEMP/HUMはSHT45を優先し、BME690を代替に使う。
SGP41は連続1Hz測定でVOC/NOx指数を維持し、暖機中・欠測は空白にする。
HCHOは未接続なら空白。CSVにはraw値も保存する。

起動時にSDの保存済み履歴を復元する。iPhoneからOT時計同期したUTC付き記録は
再起動をまたいで直近24時間へまとめる。旧CSVや時計未同期の記録は、その起動sessionの
経過時間として表示し、電源OFF中の長さを推定して連結しない。
上ボタンで保存済み履歴、下ボタンで現在のグラフへ戻る。

PUSHは短押しを離した時にグラフ／画像を切り替える。3秒長押しでは画像切替を抑止して
PINを要求する。パネル自身の全画面更新には約15秒かかる。
画像はアプリで6色ディザへ変換し、専用BLEサービスでSDへ転送する。
新旧2スロットのcommit markerとCRCを確認し、最新の有効画像を既存120KB描画バッファへ読む。
再起動後も画像モードで保存画像を表示できる。画像未設定なら明示的なテスト画像を表示する。
[画像転送プロトコル](../../shared/protocol/card-image-v1.md)を参照。

画像表示中の1Hz測定・毎分BLE同期・10分SD保存ではパネルを再描画しない。
`card_display_refresh_periodic()`は画像モードで成功のno-opとなり、進行中の画像更新の
revisionや完了通知も変更しない。新画像のcommit、画像／グラフの切替、
明示的な再表示、PIN表示後の復帰では画面を更新する。

描画と画面更新は別スレッドで行うため、測定スケジュールを止めない。
画面更新中のモード変更は最後に選んだモードへまとめ、進行中の更新後に反映する。
同じモードの要求を重ねても、更新を無制限に追加しない。
更新後は表示器をpower off・deep sleepにする。
元サンプルとの描画比較では120,000バイト一致を確認済み。
実機でグラフの表示と約14.4秒の全画面更新を確認済み。

## SDへの一括記録

SD1をハードウェアSPI20で使用する。SCK=P1.04、MOSI=P1.06、
MISO=P1.02、CS=P2.04、最大クロック4 MHz。P1.02のNFC機能は無効にする。
SDのVDDも`+V`なので、電源投入後のセンサー初期化・最初の測定を終えてからマウントする。
表示器のCS（P1.03）は起動前にHighへ固定し、以後はSPIドライバーがそれぞれのCSを制御する。

毎秒の実測値を640件のRAM ringへ保持し、10分ごとに専用workerがSDへ追記する。
600件のバッチに加え、書込中の測定用に40件分の余裕がある。
`LOG00000.CSV`～`LOG99999.CSV`は起動ごとに未使用ファイルを選び、既存ファイルを上書きしない。
整数単位、valid mask、温湿度のソース、診断値、起動後秒数を保存し、欠測は空欄にする。
iPhoneで時計同期した後は`unix_s`列へUTC秒を記録する。0／空欄は未同期を意味する。
`boot_id`列と連番で測定を識別し、SDへ移る前後で同じ記録を二重送信しない。
旧CSVは読み込み互換を維持する。

書込はsync・close・unmountまで行い、失敗した未commit分を保持して再試行する。
ring満杯時は新しい測定行を拒否してログに出し、未保存の古い行を上書きしない。
最後のsync以降にRAMへ残った未保存分（通常は約10分＋書込待ち分、最大640行）は電源断で失われる。
SD保存済みの行は次の起動時に復元する。
現在bootの時計訂正は保存前の値と履歴転送へ反映する。新CSVでは同じbootの最後に
保存したUTCとuptimeを基準に再読出しするため、次の起動でも時計訂正を保持する。
最後のSD保存後に受けた時計訂正は、次のバッチを保存する前に電源が切れるとSDには残らない。
画像I/O・画面更新とSDのSPI操作は専用worker間で直列化し、1Hz測定threadを待たせない。
自動フォーマットは無効。

`CONFIG_CARD_TEST_CADENCE=y`は測定1秒、SD／画面40秒の検証用設定。
CSV名は`TSTxxxxx.CSV`となり、保存後の再マウント・読戻し比較を行う。
通常は`n`。`CARD_EXTRA_CONF_FILE=/absolute/path/test.conf ./scripts/fw build`で指定できる。
通常のbuild／flashではEXTRA_CONF_FILEを空へ戻す。

## スイッチの入力確認

S1（TMHU27）の端子1=P2.01、端子2=P2.02、T=P2.05を内部プルアップ付き入力にする。
C1/C2はGND。端子1は反時計回り、端子2は時計回り、Tは押し込みの接点。
ログではそれぞれ`SW UP/CCW (1)`、`SW DOWN/CW (2)`、`SW PUSH (T)`と表示する。
上下の表記は基板の向きによるため、操作して一致することを確認する。

本番設定は`CONFIG_CARD_SWITCH_POLL_MS=50`。P2にはGPIO割り込みがないため、
System ONで50msごとに接点を確認する。押下と長押しの処理は非同期で、測定を止めない。
短い操作に反応し、再登録時に1分間押し続ける必要はない。

読み取りで変化を見つけたら、方向は10 ms、押し込みは20 ms後に再確認する。
チャタリングで変化すると確認をやり直す。
押下時にカウントを増やし、押し続けている間は重複したイベントを出さない。
安定した押下を`switch_test_set_handler(card_display_button, NULL)`で表示処理へ渡す。
解放イベントは記録するが、画面は切り替えない。
SW1は電源スイッチでGPIOには接続されていない。

スイッチ信号をP0/P1へ配線変更し、DTSの端子指定を更新した後は、
両エッジ割り込みから遅延処理で同じデバウンスを行える。
これによりSystem ON待機中のCPUを操作で起こせる。配線変更後に実機で確認する。
従来のスイッチ単体テストでは、上・下・押し込み各3回の押下と解放、
カウント1・2・3、操作中の重複イベントなしを確認した。

## BLE共通プロトコル

[shared/protocol](../../shared/protocol/)のOE v1データ、OF v1通知分割、同じService/Characteristic
UUIDをoutdoorと共有する。roomにも同じschemaと共通ライブラリを使用できる。
roomのファームウェアは現時点では存在しない。
名前は `Card Sensor`。登録済みiPhoneから、認証付きLE Secure Connections（L4）で
Readの最新1回分、Notifyの新しい測定1回分を取得できる。
SFA40未接続はエラーTLVとなり、値を捏造しない。VOC/NOx指数のvalidは暖機状態に従う。
認証済みiPhoneのOT v1（UTCミリ秒）を[専用時計サービス](../../shared/protocol/env-clock-v1.md)
で受け取り、測定時刻とSDのUTC列に使う。旧環境特性へのOT Writeも維持する。
再電源投入後は再同期まで時計未確定として扱う。

[履歴サービス](../../shared/protocol/env-history-v1.md)では、毎秒の記録を最大6件のページに
分けて送る。通常の1分分は60件で、スマートフォンは保存済みカーソルからPULLし、
SQLiteへ耐久保存した後にACKする。通信できなかった分も同じ手順で取得する。
ページはACKまで固定し、Read Blobの途中で新しい測定や時計同期が来ても変更しない。
連続ページではファイル位置と必要なメタデータを再利用し、全SDファイルを毎回走査しない。
再接続・CSV追記・書込失敗からの巻き戻しではキャッシュを更新する。
時計同期前に取得した現在bootの時刻は、同期後のanchorで補える。
別bootの未知UTCは推定せず、電源断で失われた未保存RAMは欠落として扱う。

通常は1分ごとの同期時に5秒間、100ms間隔の接続可能な広告を出し、接続先へ通知する。
履歴取得・画像転送・認証済み通知の進行中は通信期限を延長する。
履歴転送の接続条件は15〜30ms、latency 0、supervision timeout 6秒。
実機で30ms／latency 0への交渉を確認した。履歴ページの準備は最大300秒、
準備済みページの無進捗待ちは120秒、完了後は5秒の応答待ちを確保する。
Cardは処理完了後の通信窓の終了時に広告を止め、接続の切断後に`bt_disable()`でBLEを停止する。
`CONFIG_BT_UNINIT_MPSL_ON_DISABLE=y`と動的割り込み設定を使い、MPSLも停止する。
次の毎分の送信時に`bt_enable()`で再開するため、受信側は各1分の通信窓で
再接続する必要がある。
既存outdoor受信コードとワイヤー形式は共通だが、スマホ側は各通信窓で再接続する必要があり、
バックグラウンド受信にはOSによる制限がある。

## 実機での周期動作確認

履歴・時計サービス追加後、通常設定を書き込み、1Hz測定を続けながらiPhoneへ
履歴ページを送れることを確認した。600行のSD保存、約7万件のUTC履歴復元、
保存したbondによるL4接続を確認している。ホストではSD・表示26ケースと、
実際のSD読出し／共通codec／GATT処理を組み合わせた4ケースのASan・UBSan検証が通った。
GATTの環境value=18・CCC=19と画像の既存handleを維持し、履歴27〜34・時計35〜39を追加した。
通常版RAMは254,540B／262,144B。履歴threadのstackは5KiB。

2026-10-13に通常設定で、714回の測定開始間隔がすべて1000 msであることを確認した。
10分後に600行を`LOG00005.CSV`へsyncし、約14.4秒の表示更新中も1Hz測定を続けた。
書き込み後の再起動では、この600行をSDから読み込み、以前のグラフを復元した。
保存したiPhoneのbondも再読み込みし、同じBLE identityでL4接続へ戻った。
画像サービス追加時に環境サービスのGATT handleが移動し、iPhoneの古いCCC登録が
`writing is not permitted`となる問題を修正した。環境value=18、CCC=19を維持し、
画像サービスを末尾へ追加する。修正後は実際のiPhoneで通知登録、1分ごとの通知、
OT時刻同期を確認した。MTU 23で19分割された通知でも時刻同期まで成功した。
この接続時はiPhoneのロック画面を確認している。iOSによるプロセス終了からの
状態復元と、実機での画像転送は未確認。
時刻同期後の600行をSDへ保存して再起動し、同期前の4行を除く596行がUTCの
保存グラフへ復元されることも確認した。

以下は以前の周期設定で行った検証。
加速設定（20秒測定・40秒SD・80秒表示）で、SDのsync後に再マウントし、
書き込んだ全行の読戻し一致と、グラフ・画像・グラフの画面更新を確認した。
本番設定へ戻して、連続した測定値を60秒間隔でBLE受信できることも確認した。
受信したOE/OFフレームはoutdoorの実際のTypeScript decoderで解析し、
センサー値とメタデータ、欠測SFA40、RAW/Indexの有効フラグを確認した。
ReadとNotifyの同じフレームはバイト単位で一致し、値はRTTの測定ログとも一致した。
通信窓の終了後にBLE/controller/MPSLを停止し、次の測定で同じidentityを使って
再開・再接続できることを確認した。電池寿命の測定は行っていない。

## CPU・センサーの動作

System OFF／deep sleepの電源管理policyは使わない。RTOSの処理待ちではSystem ONの
通常idleへ戻り、測定は1Hz、スイッチ確認は50msで続く。
SGP41・STCC4・OPT4001は連続測定、BME690は毎秒forced測定。
SFA40実装後は内部連続動作を保ち、各秒の読み取りへ加わる。
BLEは通常1分周期、履歴取得・画像転送中は接続期限を延長する。電池寿命の実測は未実施。

STCC4は新しい測定バッファを最大200ms待ち、空のままならその回のCO₂を欠測にする。
実機では約95回に1回、マイコンの1秒周期に新しいCO₂が間に合わなかった。
成功するまでの待ち時間が周期ごとに増え、欠測後に短い待ちへ戻るため、
両者の測定時計の相対的なずれと一致する。古い値を新しい実測値として保存しない。
STCC4の[公式D1データシート](https://sensirion.com/media/documents/6AED4B15/69295E41/CD_DS_STCC4_D1.pdf)
の測定周期は1000±150msなので、マイコンの固定1秒周期ごとに
新しいCO₂が必ず揃うことは保証できない。

## iPhoneとの安全な登録

初回はCardの電子ペーパーに毎回新しい6桁番号を表示し、その後180秒間広告する。
iPhoneアプリから接続し、OSのペアリングダイアログに画面の番号を入力する。
番号は先頭の0を含む6桁。固定PINや共有パスワードは使わない。
電子ペーパーの描画が終わるまで広告しないため、14秒程度の表示待ちが
BLE標準の30秒入力期限を消費しない。失敗した場合は接続を閉じ、
新しい番号を表示してから再び広告する。登録中は通常のグラフ・画像更新を抑止する。

登録完了後は6桁番号の画面を解除して、通常の画面に戻す。
同じiPhoneの鍵で毎分の接続を暗号化し、通常は5秒の通信窓へ戻る。
Read/Notify/CCC/clock WriteすべてにSC＋MITMのL4を要求する。
登録窓外では新しいpairingを拒否し、既存ownerを自動的に置き換えない。

機種変更や鍵の不一致時は、PUSH（押し込み）を3秒間続けて押す。
50msポーリングで押下を検出し、3秒経過で長押しを確認する。
長押しが成立したらボタンを離してよい。電子ペーパーの描画が完了すると番号が表示される。
確認後に古いiPhoneのbondを削除し、新しい6桁番号の登録窓を開く。
iPhone側にも古い登録が残っている場合は、Bluetooth設定でCardの登録を解除して再接続する。
長押し検出後は接点を解放するまで繰り返し鍵を消さない。

鍵とBLE identityは内蔵RRAMの最終36 KiB（`0x174000..0x17cfff`）に
Zephyr ZMS settingsとして保存する。SDカードには保存しない。
各 `bt_enable` の直後にBluetooth settingsを読み込み、bondとidentityを戻す。
初回identity書込の完了と保存内容の一致を確認してからBLEを停止する。
登録時は保存bondの存在、再登録時は古いbondの削除を確認する。
保存に失敗したまま登録完了を宣言しない。
通常のアプリHEXにはsettings領域を含めないので、通常書込では維持される。
全消去/recoverやsettings範囲の上書きは登録を失うので、再登録が必要になる。
この開発設定ではSWDを有効にしているため、物理デバッガーでの鍵読出しを防ぐ設定ではない。

2026-10-11に実機で、初回identityの同期保存・再読一致、電子ペーパーのPIN描画完了後の
180秒広告、60秒間隔の実測、登録窓終了時のcontroller/MPSL停止を確認した。
次の測定で保存identityを再読み込み、通常の5秒通信窓を開いて再び停止する動作も確認済み。
ホスト状態テストとCard/Outdoorビルドも確認した。
その後、iPhoneの保存鍵によるL4接続と、通常のファームウェア書き込み・再起動後の
bond再読み込みを確認した。ロック画面中の通知・時刻同期も確認した。
電源ケーブルを抜いた復帰と、iOSによるプロセス終了からの復元は未確認。
