# 環境センサー iPhoneアプリ

card・outdoor・room共通のBLEプロトコルで測定値を受信し、iPhone内に蓄積するSwiftUIアプリ。iOS 26以降、Xcode 26 / Swift 6.2を使用する。

## できること

- 近くのセンサーを検索・登録し、複数の機器から受信する。
- 登録済みの機器へ接続を待ち、バックグラウンドのBLEコールバックで保存する。
- 温度・湿度・CO₂・照度・気圧・VOC raw・NOx raw・ホルムアルデヒドの最新値と履歴を表示する。
- 複数の項目を同じ時間軸のグラフで見比べる。1時間・6時間・24時間・7日・任意の時間範囲を選び、拡大・移動・指定時刻の値の確認ができる。
- cardの毎秒の記録をページ単位で受け取り、未受信分も再接続後に続けて保存する。グラフだけ表示範囲に応じて集約し、保存する元データは間引かない。
- JSON / CSVを書き出し、iOSの共有画面でファイルを渡す。
- 全体・機器ごとに受信を停止／再開する。停止しても履歴は残す。
- 接続後にiPhoneのUTC時刻を本体へ同期する。応答を受けた場合だけ同期済みとして扱う。
- 写真を回転・トリミング・拡大し、明るさ・コントラスト・彩度を調整する。6色プレビューを確認してcardの電子ペーパーへ送信し、本体のSDカードに保存する。

IoTサーバーへの送信処理は後回し。接続先・認証方式が決まったら、保存済みの連番からバッチを取得する `SensorStore.exportBatch(afterID:limit:)` に送信処理を接続できる。

## 起動

1. `EnvSensor.xcodeproj` をXcodeで開く。
2. `EnvSensor` ターゲットの **Signing & Capabilities → Team** で開発用Teamを選ぶ。必要ならBundle Identifierも自分のものへ変更する。
3. 接続したiPhoneを実行先に選び、Runする。開発用端末ではDeveloper Modeを有効にする。
4. アプリのBluetooth使用を許可し、「デバイスを追加」からセンサーを登録する。
5. セキュリティ対応cardでは、iPhoneのペアリング画面へ電子ペーパーに表示された6桁の番号を入力する。

アプリの機器登録は受信対象の選択。BLEのペアリング／ボンディングはiOSが扱う別の処理で、アプリに鍵やパスキーを保存しない。ペアリング済みなら、以後はiOSの保存した鍵で暗号化して再接続する。

ペアリング情報が片側だけ消えた場合は、iPhoneのBluetooth設定に機器があれば登録を解除し、card側も再登録モードにする。cardの物理操作・登録窓は [firmware README](../firmware/README.md) を参照。

## 電子ペーパーの画像

1. cardの機器カードで「画像」を押す。
2. 「写真を選ぶ」から写真を選ぶ。
3. 「配置・トリミング」で元写真を大きく表示し、白い3:2枠の内側に残す部分を選ぶ。ドラッグで位置、ピンチで倍率を調整する。全体表示／トリミング、回転、倍率・位置のスライダーも使用できる。
4. 「元の写真」と「6色の結果」を切り替えて配置を確認し、「配置を完了」で戻る。
5. 自動明暗補正・発色・明るさ・コントラスト・彩度を調整して6色の仕上がりを確認する。色と配置はそれぞれリセットできる。
6. 「cardへ送信」を押す。未接続なら、次の通信を待って自動で転送を始める。待機は通常最大約1分。
7. 「cardに画像を表示しました」となるまで、アプリを開いておく。

全体表示では写真を横600×縦400ピクセルへ収め、余白を白にする。トリミングでは画面を埋めるように拡大し、切り取る位置を選ぶ。配置UIと変換処理は同じ座標・倍率の計算を使う。

初期状態では自動明暗補正と発色強調を使用する。写真の淡い色を中心に強め、元の無彩色・白余白・透明領域は着色しない。調整後の画像に黒・白・黄・赤・青・緑の蛇行Floyd–Steinbergディザを適用して方向の偏りを減らし、同じ変換結果からプレビューと送信データを作る。プレビューと実際のパネルの色は一致するとは限らない。

本体の画像モードでは定期的にパネルを再描画しない。測定・同期・SD保存を続けながら画像を保持し、新しい画像の送信やスイッチによる表示切替で更新する。

画像転送は環境測定と別のBLEサービスを使い、同じLE Secure Connectionsの認証とbondで保護する。各chunkのWrite応答の後、本体のStatusからSDに保存された位置を確認して次を送る。CRC・サイズ・全ピクセルの色コードが正しい画像だけをcommitし、パネル更新完了までStatusを確認する。単に送信が終わった時点では、表示成功とは報告しない。

通信待ちと送信中は、アプリを閉じる・収集を停止する・転送を中止する操作で転送を中止できる。通信待ちの画像は前景でのみ保持し、キャンセルや背景移行で破棄する。転送開始は同じ登録機器から完全な測定を認証付きで受信した後に限る。

送信を中止した後はいったんBLEを切断し、以前のWrite応答が次のBEGIN応答と混ざらないようにする。次の画像はすぐ待機キューへ入れられるが、新しい接続で認証を確認するまでBEGINは送らない。

COMMITを送った時点から中止はできない。保存・画面更新が始まると処理は本体で続き、アプリを開き直した時に接続してStatusを確認する。転送途中の画像を再開する機能はなく、再送は先頭から行う。cardのSDカードが必要。新旧2スロットで保存するため、COMMIT前の失敗なら以前の有効画像が残る。詳細は [Card image transfer v1](../../shared/protocol/card-image-v1.md) を参照。

### プロジェクトの再生成

Xcodeプロジェクトは生成済み。ソースファイルを追加した場合は、XcodeGenで生成し直す。

```sh
cd card/software
xcodegen generate
```

依存ライブラリはAppleのSwiftUI・CoreBluetooth・Charts・SQLiteのみ。外部パッケージの取得は不要。

## バックグラウンド動作

`UIBackgroundModes` の `bluetooth-central` とCoreBluetoothの状態復元を使用する。最初の検索・登録はアプリを開いて行う。以後は登録UUIDごとの接続要求をiOSに保持させ、cardの次の通信窓で再接続する。アプリ自身の1分タイマーやバックグラウンドの連続スキャンは使わない。

通常の画面ロック・他アプリへの切り替えでは、受信イベントに応じてアプリが起こされる。OSがプロセスを終了した場合は状態復元を使用する。ユーザーがアプリをスワイプして強制終了した場合は、一度開くまで自動受信できない。Bluetoothの許可、給電、電波到達も必要。

毎分の受信を保証するものではない。iOSの制御や電波状況で取り逃した場合、履歴サービスに対応したcardからSDと未書込RAMの記録を再接続後に取得する。SQLiteへページと再開カーソルを同じtransactionで保存してからACKを返す。途中で切断しても、次の接続では耐久保存したカーソルから続ける。最新値だけのOE v1を使う旧ファームウェアは、この再送に対応しない。

DBとWAL/SHMファイルは `completeUntilFirstUserAuthentication` を使用し、一度ロック解除した後は画面ロック中も書ける。iPhone再起動後は、まず一度ロック解除する。ファイル共有・大きな履歴表示はアプリを開いて行う。

詳細は [AppleのCoreBluetoothバックグラウンド処理](https://developer.apple.com/library/archive/documentation/NetworkingInternetWeb/Conceptual/CoreBluetooth_concepts/CoreBluetoothBackgroundProcessingForIOSApps/PerformingTasksWhileYourAppIsInTheBackground.html) を参照。

## 保存と表示

保存先はアプリ専用の `Application Support/EnvSensor/readings.sqlite`。SQLiteのWAL・FULL同期で、BLEのコールバック内でコミットしてから処理を返す。同じ測定のReadとNotifyは1件にまとめ、同じ接続内で遅れて届いた古いReadは除外する。

通知の先頭や途中が欠けた場合は、不完全な測定を保存せず、特性のReadで最新の完全な値を取り直す。状態復元後のReadですでに取得した測定の通知後半は、保存済みフレームと各バイトを照合して重複として扱う。内容の不一致・壊れた状態フラグ・不正な長さは引き続きエラーにする。未接続のSFA40など、正常なフレームに含まれるセンサーの未取得状態とは区別する。

履歴サービスでは、機器識別子・boot ID・連番・稼働時間・本体の測定UTC・iPhoneの受信時刻・センサー値と有効フラグ・元のレコードを保持する。同じ機器・boot・連番を重複保存しない。接続後の時計訂正では、同じbootの測定時刻だけを修正し、測定値を変更しない。未同期UTCは未知として保存し、過去の別bootの時刻を推定しない。指定カーソルを本体が失っていた場合は欠落を表示し、残っている最古の記録から重複をまとめて再走査する。

旧OE v1のみの機器では、再起動を稼働時間の低下から推定し、受信時刻を表示に使用する。履歴サービス対応機器のOE最新値は、過去の記録を取得中でも最新状態を確認できる一時表示として使い、履歴DBには重複保存しない。

未取得・センサーエラーの値は「—」。VOC / NOxの画面表示はraw値で、指数や濃度として扱わない。受信した指数とその有効フラグも元データに保存する。未接続のSFA40は正常な未取得状態で、BLE通知の欠落としては扱わない。SFA40は `ready` と `within_specification` を満たす値だけ表示する。グラフでは未取得・機器再起動・長い欠測をまたぐ線をつながない。時刻が未確定の履歴は件数を案内してグラフから除外する。

認証後、専用の[時計サービス](../../shared/protocol/env-clock-v1.md)へ `OT` v1形式（UTC Unixミリ秒）をWrite with responseで送る。接続ごとに一度同期し、成功応答後に履歴PULLを始める。時計サービスがない旧ファームウェアでは環境特性へのOT Writeを使用する。時計対応がない機器でも、従来の測定受信は継続する。

## 履歴の操作

履歴画面は「重ねる」と「項目別」を切り替えられる。初期は全8項目を表示し、取得済みの値を一つのグラフへ重ねる。未取得の項目も値カード・凡例に「—」で残す。「目盛りを選ぶ（最大3項目）」で実単位の目盛りを選ぶ。目盛りは画面幅に合わせて最大3項目表示するが、選択した全項目の線・値・範囲は表示する。

時間範囲は全項目に共通。グラフを1本指でタップ・左右にドラッグすると、その時刻の実測値をまとめて表示する。2本指の間隔を変えると拡大・縮小し、2本指を左右に動かすと時間範囲を移動する。ズームと移動は同時にでき、指の中心にあった時刻を保つ。1本指の縦ドラッグは画面のスクロールに使う。前後への移動と最新への復帰、開始・終了日時の指定、拡大・縮小ボタンにも対応する。

「縦軸を固定」をONにすると、その時点で表示している各項目の縦軸範囲を維持する。時間の移動・ズーム・新しい記録の受信でも範囲を変えない。OFFに戻すと、表示期間の値から範囲を計算する。固定範囲を超えた値も保存と数値表示は保持し、グラフの描画だけを範囲内に切り取る。重ね表示と項目別表示で同じ固定範囲を使う。重ね表示の縦軸はそれぞれ独立しており、同じ高さが同じ数値を示すとは限らない。

描画用の集約間隔は表示期間に応じて変わる。短い範囲では1秒の元データへ戻り、長い範囲ではSQLで点数を抑える。履歴の検索・集計と系列・尺度の準備は背景で行い、結果をまとめて画面へ反映する。専用の読み取り接続を使うため、集計中もBLEの保存を続けられる。保存通知によるグラフ更新は3秒間隔にまとめ、期間変更はすぐ反映する。カーソル操作では保存データを再集計せず、準備済みのグラフと時刻索引を使う。系列をまとめて描くLinePlotと、独立したカーソルの表示を使用する。CSV / JSONの書き出しは選択期間の元データを使用する。

JSONは `env-sensor-export-v1` 形式で機器一覧と測定一覧を含む。CSVは全センサーのフィールドと元の整数単位を保持する。64bitの識別子は文字列として保持し、整数精度を落とさない。

## 検証

履歴・時計・範囲選択・重ね表示と背景集計を追加した版は、82件のコアテスト、Simulator Debugと署名付きiPhone Debugのビルドを確認した。実機へ保存データを維持して更新し、毎秒の履歴ページと耐久カーソルの保存、アプリ再起動後の続き取得、重複キーなしを確認した。旧SD記録でUTCが不明な行は、未知時刻のまま保存している。

Simulatorでは複数項目、時間範囲、日時指定、時間移動、ピンチ、共通カーソルを操作した。欠測通知・解除ボタン・グラフの時刻行は領域を常時確保する。記録あり→欠測→記録ありと横へドラッグした際、湿度・CO₂の見出しと書き出し領域の座標が変わらないことを確認した。
重ね表示では全8項目の初期選択、未取得HCHOの「—」、3本の実単位軸と線の色・線種の対応、軸の表示切替、共通カーソルの値を確認した。2026-10-14の背景集計版は、実データと別のDBに1秒周期の24時間分（86,400件）を用意して操作した。全項目表示・ドラッグ・ピンチ拡大・欠測区間でのレイアウト安定を確認した。背景読取りの単体テストでは、集計の読取りtransaction中も別接続から保存できること、キャンセル後の保存、古い履歴だけ変わった場合の更新通知を確認した。読み上げには正規化した座標を使用せず、実単位のテキストと前後の測定を選ぶアクションを提供する。

二本指操作の追加後は、同じ86,400件のデータで、二本指だけの平行移動・ズーム・両方を同時に行う操作を確認した。縦軸固定ONでは範囲を保ち、OFFで自動計算へ戻る。項目別表示でも二本指で期間が移動することを確認した。一本指の横移動ではカーソルを更新し、表示期間を変えない。グラフ内からの一本指の縦ドラッグでは画面がスクロールし、表示期間を保つ。
